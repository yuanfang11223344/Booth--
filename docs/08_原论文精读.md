## 2. Booth 究竟解决了什么

论文讨论当时机器中的带符号乘法：若正负数分开处理，会引入额外的符号判别与校正过程。Booth 想用同一套加、减、右移步骤处理两输入的各种符号组合。另一个观察是连续一串 1 可改写为两端的差，例如 `00111100₂ = 01000000₂ − 00000100₂`。对乘数的一段 1，逐位累加可由边界处一次加法和一次减法替代。这解释了编码的**来源**，但不意味着每种输入都更快。

我的理解：论文的关键不是发明另一种乘积，而是改变乘数的表示及部分积的生成时机；乘法器仍实现同一个数值函数。现代硬件究竟节约多少面积或时间，取决于加法结构、寄存器、位宽与目标器件，不能从 1951 年的设备经济动机直接推断。

## 3. 对照原文规则，避免读反加减号

原文记乘数为 `m`、被乘数为 `r`。它的位序写作 `m₀.m₁…mₙ`，`m₀` 在高位端，处理从最低有效位开始。因此原文比较的是 `(mₙ, mₙ₊₁)`，其中 `mₙ₊₁` 是当前位**右边**已经处理过的邻位；起始边界取 0。扫描第 3 页列出的规则是：

| 当前位、右邻位 | 原文操作 | 现代 `({q_i,q_{i-1}})` |
| --- | --- | --- |
| `00` | 仅右移 | 不加部分积 |
| `01` | 加 `r` 后右移 | `+M` |
| `10` | 减 `r` 后右移 | `−M` |
| `11` | 仅右移 | 不加部分积 |

原文还明确写了两项容易漏掉的细节：**到 `m₀` 时不再执行右移**；在初始最低位之外预设邻位为 0。原文的位权采用小数点形式 `m₀·2⁰ + m₁·2⁻¹ + …`，证明中按其定点表示作模 2 运算。本工程的 RTL 则使用 W 位二补码**整数**与完整 `2W` 位结果。这是相同相邻位思想的现代定点缩放/整数改写，不能把原文的下标、末次移位或模 2 记法逐字搬到 RTL。

## 4. 我对数学论证的重建

以下是面向本工程整数接口的推导，**不是原论文原式的逐字转录**。设 W 位乘数的位 `q₀…q_{W−1}`，符号位 `q_{W−1}`，并令 `q_{−1}=0`。定义 `d_i=q_{i−1}−q_i`，则 `01` 给 `+1`、`10` 给 `−1`，其余给 0：

```text
Σ(i=0..W−1) d_i·2^i
= Σ(i=0..W−1) (q_(i−1)−q_i)·2^i
= Σ(i=0..W−2) q_i·2^i − q_(W−1)·2^(W−1)
= signed_W(q)
```

第二行到第三行由相邻项消去得到，最后一项恰好是二补码符号位的负权重。乘以 `M` 后，每个非零 `d_i` 对应 `±(M << i)`，总和仍是 `M × signed_W(q)`。这同时说明为什么无需在末尾另设一个“若负则修正”步骤。

论文第 3 页从单个位的贡献证明该步骤：其加减边界产生 `−r·2⁻ⁿ + r·2^(−n+1) = r·2⁻ⁿ`，再处理高端符号位。我的整数推导与这个论证同源，但采用了不同的位权与记号。

## 6. 原文给了什么证据，仍需验证什么

原文给出规则、正确性论证和正负号组合的算例。这足以解释算法的数学意图，但没有本工程的 RTL、现代测试覆盖、形式证明或 ASIC/FPGA PPA 数据。对于长串 1，加减事件通常比逐位加少；对于交替 0/1，非零事件可能很多。即使事件少，迭代乘法器仍需时钟周期，组合乘法器的关键路径也可能由译码与加法网络决定。

因此“能替代”需要分两层判断：在相同输入解释、输出宽度和握手时序约定下，数值等价可由[仿真与形式验证](06_综合与形式验证.md)检查；面积、时序、功耗的优势则必须放到目标工艺/FPGA 的同一约束与布局布线流程中测量。原论文支持前者的数学依据，不能作为后者的现代实测结论。

### 阅读时自查

1. 用 `00111100₂ = 01000000₂ − 00000100₂` 找出一段连续 1 的两个边界。
2. 在原文第 3 页确认 `01` 是加、`10` 是减，且 `m₀` 那一步不右移。
3. 对 W=4 的 `q=1001₂` 代入 `d_i=q_(i−1)−q_i`，得到带符号值 `−7`；再运行 `python3 scripts/recode.py 4 3 -7` 对照工程输出。
